# 睡前復盤 2026-11-27：子集合

嗨，晚安。歡迎收聽今天的睡前程式復盤。今天的題目是 Subsets，列出一個陣列所有的子集合。這是回溯法，也就是 backtracking 的第一題，後面很多題目，像是組合、排列、組合總和，都是從這個框架長出來的。所以今晚我們慢慢把它想透。放輕鬆，我們開始。

## 題目

題目是：給你一個整數陣列 nums，裡面的數字都不重複，回傳它所有可能的子集合，包含空集合和它自己。順序不拘。

如果陣列有 n 個數字，每個數字都有「選」或「不選」兩種可能，所以總共有 2 的 n 次方個子集合。這也告訴我們，不管用什麼方法，光是把答案寫出來，就至少要 2 的 n 次方乘以 n 的時間，所以這題沒有什麼「更快」的捷徑，重點在於把所有可能有條理地走一遍，不重複也不遺漏。

## 你的解法：回溯

你的做法是經典的回溯。準備一個 path，代表「目前正在組的子集合」，還有一個 res，用來收集答案。

遞迴函式 traversal 做的事情是這樣：一進來，先把目前的 path 放進答案裡。然後從 idx 的下一個位置開始，往後的每一個數字，都試著把它加進 path，遞迴下去，回來之後再把它拿掉。

這個「加進去、遞迴、拿出來」的三步驟，就是回溯法的靈魂。想像你在走一個迷宮，每到一個岔路，你先走進其中一條，走到底之後，原路退回岔路口，把腳印擦掉，再走下一條。path 的 push_back 是踏出去，pop_back 就是退回來，讓 path 回到進來之前的樣子，下一個選擇才不會被上一個污染。

為什麼一進來就把 path 放進答案，而不是等到走到底？因為在這題裡，每一個中間狀態都是一個合法的子集合。空集合是第一個被加入的，接著是只有第一個數字的，然後是第一和第二個，依此類推。這跟之後的排列題不一樣，排列題要等到長度滿了才收答案。

另外一個關鍵是迴圈從 idx 加一開始。這保證了每個子集合裡的數字，索引都是遞增的。所以你只會產生「一、二」，不會再產生「二、一」，這就是避免重複的方法。你一開始傳入負一，讓第一層的迴圈從零開始，這個小技巧很乾淨。

## 可以改進的地方

有一個值得注意的細節：你的 traversal 參數裡，nums 是用傳值的方式，也就是 vector 不加參考符號。這代表每一次遞迴呼叫，都會把整個 nums 陣列複製一份。總共有 2 的 n 次方次呼叫，每次複製 n 個元素，雖然漸進複雜度跟產生答案的成本一樣，但這是完全不必要的額外工作，還會多用很多記憶體。

改法很簡單：把參數改成 const vector int 參考。const 表示我不會修改它，參考表示不要複製。你在 path 和 res 都已經用了參考，nums 也一起加上就好。這是 C++ 寫遞迴時很常見的效能陷阱，面試官很可能會注意到，養成習慣就不會忘。

## 另一種想法：位元遮罩

最後來跟前幾天的位元題串起來。剛剛說過，每個數字都有選或不選兩種可能，這不就像一個 n 位元的二進位數字嗎？第 j 個位元是 1，就代表選第 j 個數字；是 0 就不選。

所以，只要讓一個計數器 mask 從零跑到 2 的 n 次方減一，對每一個 mask，檢查它的每個位元，是 1 的位置就把對應的數字放進子集合。這樣就能不用遞迴，直接列出所有子集合。

例如 n 等於三，mask 是五，二進位一零一，就代表選第零個和第二個數字。你看，前天學的「看某個位元是不是 1」，在這裡又派上用場了。

另外還有第三種寫法，叫做「選或不選」的二元遞迴：對每個數字，分成選它和不選它兩條路，走到陣列尾巴時才收答案。三種方法的複雜度都一樣，但回溯框架最有延展性，是後面所有回溯題的基礎。

## 今晚的重點回顧

好，我們收一收今天的重點。

回溯三步驟：加進去、遞迴、拿出來。拿出來是為了讓狀態回到原樣。

子集合在每一層一進來就收答案，因為每個中間狀態都合法。

迴圈從上一個索引的下一個開始，保證不重複。

C++ 遞迴時，不會修改的大型參數，記得用 const 參考，避免每層都複製一次。

另一種角度：n 個數字的子集合，對應零到 2 的 n 次方減一的每一個二進位數字。

留一個小問題陪你入睡：如果 nums 裡面有重複的數字，例如一、二、二，怎麼修改你的回溯，才不會產生兩個一樣的子集合？提示一下：先排序，然後想想在同一層的迴圈裡，遇到跟前一個一樣的數字該怎麼辦。這就是下一題 Subsets II。不用急著回答，讓它在夢裡慢慢想。
