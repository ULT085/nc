# 睡前復盤 2026-11-23：位元 1 的個數

嗨，晚安。歡迎收聽今天的睡前程式復盤。今天的題目是 Number of 1 Bits，計算一個整數的二進位表示裡有幾個 1。這是位元運算的入門題，而你寫了兩個版本，剛好代表兩種很不一樣的思考方式。放輕鬆，我們慢慢走一遍。

## 題目

題目是：給你一個 32 位元的無號整數 n，回傳它的二進位表示中，有幾個位元是 1。這個數量也有一個正式的名字，叫做漢明重量，Hamming weight，也就是函式名稱 hammingWeight 的由來。

## 第一個版本：一位一位看

你的第一個版本，用的是我們從小學十進位轉二進位的方法。每一輪，先看 n 除以二的餘數，餘數就是 n 最右邊那一個位元，是一就加一，是零就加零。然後把 n 除以二，等於把整個數往右推一格，把剛剛看過的那個位元丟掉。重複到 n 變成零為止。

想像你手上有一串燈泡，你每次只看最右邊那顆亮不亮，看完就把它拔掉，讓下一顆遞補到最右邊。全部拔完，你就數完了。

這個版本很直覺，而且正確。這裡要提一個細節：n 的型別是無號整數，所以除以二就等於右移一位，不會遇到負數右移時補一的問題。如果改用位元運算的寫法，餘數二可以寫成 n and 1，除以二可以寫成 n 右移一位，意思完全一樣。

它的時間複雜度取決於 n 最高的那個 1 在哪裡。最壞的情況下，最高位是 1，要跑滿 32 輪。

## 第二個版本：每次消掉一個 1

第二個版本就很漂亮了。迴圈裡只有一行：n 等於 n and n 減一。每做一次，計數就加一，直到 n 變成零。

為什麼這行有用？關鍵在於 n 減一，會對二進位做什麼事。減一的時候，最右邊的那個 1 會被借位變成 0，而它右邊原本的那些 0，全部變成 1。左邊的部分完全不動。

舉個例子。假設 n 是一零一零零，n 減一就是一零零一一。你看，最右邊的那個 1 變成 0，它右邊的兩個 0 變成兩個 1，最左邊的一零保持不變。這時候把兩者做 and：左邊相同的部分保留下來，最右邊那個 1 以及它右邊的位置，因為一邊是 0、一邊是 1，and 起來全部變成 0。結果是一零零零零，剛好就是把最右邊的那個 1 消掉了。

所以 n and n 減一，這個運算的意義就是：消掉最右邊的那個 1。每消一次就數一次，數到 n 變成零，你就知道總共有幾個 1。

回到燈泡的比喻：第一個版本是一顆一顆檢查，不管亮不亮都要看；第二個版本是直接找到下一顆亮著的燈，把它關掉，暗的燈完全跳過。

所以第二個版本的迴圈次數，剛好就是 1 的個數。如果 n 只有一兩個 1，就算它們在很高的位置，也只要跑一兩輪。

## 延伸

這個 n and n 減一的技巧非常值得記住，因為它在很多題目都會出現。例如判斷一個數是不是 2 的次方：2 的次方在二進位裡只有一個 1，所以只要 n 大於零，而且 n and n 減一等於零，它就是 2 的次方。另外，NeetCode 的位元運算章節裡，下一題 Counting Bits 也可以用它：i 的 1 的個數，等於 i and i 減一的 1 的個數再加一，變成一個漂亮的動態規劃。

在實際寫 C++ 的時候，也可以直接用內建函式 builtin popcount，編譯器通常會把它轉成 CPU 的單一指令。面試時可以提一句，但面試官通常還是想聽你親手實作。

兩個版本的空間都是常數。時間方面，第一版跟最高位的位置有關，最多 32 輪；第二版只跟 1 的個數有關。
