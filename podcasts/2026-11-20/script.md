## 第一題：相同的二元樹

先從暖身題開始。題目是：給你兩棵二元樹的根節點 p 和 q，判斷這兩棵樹是不是完全一樣，也就是結構相同，而且每個位置的值也相同。

你的解法是很乾淨的遞迴，三行就寫完了。第一行：如果 p 和 q 都是空的，代表兩邊同時走到盡頭，回傳 true。第二行：如果只有其中一個是空的，結構不一樣，回傳 false。走到第三行，代表兩個節點都存在，那就要求左子樹相同、右子樹相同，而且這兩個節點的值也相同。

這兩個空指標的判斷順序很重要。一定要先判斷「兩個都空」，再判斷「其中一個空」。如果順序反過來，兩個都空的情況會被第二行誤判成 false。

有一個小地方可以優化：你把值的比較放在最後面。因為 and 運算會短路，如果把 p 的值等於 q 的值放在最前面，當根節點的值就不一樣時，就能立刻回傳，不必先遞迴走完整棵左子樹。結果一樣，但在不同的樹上會更快結束。

時間複雜度是 O(n)，每個節點看一次；空間是遞迴深度，也就是樹的高度。關鍵句：「兩個都空才算相同，一個空就不同，再比值、比左、比右」。

## 第二題：最長公共子序列

第二題是動態規劃的經典：最長公共子序列。給你兩個字串，找出它們最長的共同子序列長度。子序列不用連續，但順序要保持。

你的第一個版本用二維表格。dp 的 i、j 代表「text1 的前 i 個字元」和「text2 的前 j 個字元」的答案。轉移只有兩種情況：如果這兩個字串的最後一個字元相同，那這個字元一定可以放進答案裡，答案就是左上角的 dp 加一。如果不同，那至少有一邊的最後一個字元用不到，就取「丟掉 text1 最後一個字」和「丟掉 text2 最後一個字」兩者的較大值，也就是上面和左邊取最大。

你把表格多開了一行一列，讓第零行和第零列都是零，代表空字串。這樣迴圈從一開始，取字元時用 i 減一、j 減一，就不用另外處理邊界。這是一個很值得養成的習慣。

第二個版本，你把空間從二維壓到了一維，用兩個陣列 dp1 和 dp2 滾動。dp1 是上一行，dp2 是正在算的這一行。左上角變成 dp1 的 j 減一，上面變成 dp1 的 j，左邊變成 dp2 的 j 減一。每算完一行，就把兩個陣列交換，所以最後的答案在 dp1 裡。

你還多做了一個貼心的小動作：一開始如果 text1 比較短，就把兩個字串交換，讓陣列的長度取比較短的那一邊。這樣空間就是兩個字串長度中的較小值。

時間複雜度是兩個長度相乘；空間從相乘降到較短的長度。關鍵句：「字元相同看左上加一，不同就看上面和左邊取大；只依賴上一行，就能滾動」。

## 第三題：單字接龍

第三題是單字接龍，Word Ladder。給你起始單字、目標單字，和一個單字清單。每一步只能改一個字母，而且改出來的字必須在清單裡，問最少要經過幾個單字才能變成目標單字。

你在註解裡寫得很清楚：這是一個最短路徑問題。每個單字是一個節點，只差一個字母的兩個單字之間有一條邊，所有邊的權重都是一，所以用廣度優先搜尋就能找到最短距離。

你的做法分三步。第一步，先檢查目標單字在不在清單裡，不在就直接回傳零。第二步，建圖：把起始單字當作零號節點，清單裡的單字當作一到 n 號，兩兩比較，用 helper 函式檢查是不是剛好差一個字母，是的話就連一條雙向邊。helper 裡你在差異超過一的時候就提早跳出，這是個好細節。第三步，從零號節點開始一層一層做 BFS，每處理完一層，距離就加一，一旦在鄰居裡看到目標，就停下來。

這裡要特別想清楚回傳值為什麼是距離加一。題目問的是「單字的數量」，不是「步數」。當你在第一層的鄰居裡就找到目標時，dis 會變成一，回傳二，也就是起始單字加上目標單字，剛好兩個字。數到這裡就對上了。

可以思考的優化是建圖這一步。兩兩比較是 n 平方乘上單字長度，清單很大時會比較慢。常見的改進是用萬用字元當作中間節點，比如把 hot 拆成星號 ot、h 星號 t、ho 星號，同一個模式下的單字互為鄰居；或是直接對每個位置把字母從 a 換到 z，查雜湊集合有沒有這個字。這樣就變成 n 乘上長度乘上二十六，不用先把整張圖建出來。

關鍵句：「每步權重都一樣，最短路徑就用 BFS 一層一層走；問的是單字數，答案要多加一」。

## 第四題：多餘的連線

第四題是 Redundant Connection。一張原本是樹的無向圖，被多加了一條邊，變成剛好有一個環。請你找出可以刪掉、讓它變回樹的那條邊，如果有多個答案，回傳在輸入中最後出現的那一條。

你用的是併查集，而且寫成一個獨立的 DSU 類別，結構很漂亮。概念很簡單：依照順序一條一條加邊，每加一條邊之前先問：這兩個端點是不是已經在同一個集合裡了？如果已經連通，再加這條邊就一定會形成環，這條就是多餘的邊，直接回傳。因為你是照順序掃，第一條造成環的邊，在這個題目的條件下，就是最後出現的那一條答案。

你的 DSU 同時用了兩個優化。第一個是路徑壓縮：find 在遞迴回來的時候，把路上每個節點的父節點直接指向根，下一次查詢就幾乎一步到位。第二個是按秩合併：union 的時候，把秩比較小的那棵樹掛到秩比較大的樹下面，避免樹長得太高。你的寫法是先確保 ra 的秩比較小，再把 ra 掛到 rb 底下，只有兩邊秩相等時，rb 的秩才加一。這個邏輯是正確的。

兩個優化加在一起，每次操作的攤銷時間幾乎是常數，嚴格來說是反阿克曼函數。整體時間近乎 O(n)，空間 O(n)。關鍵句：「加邊前先問是不是已經連通，連通了就是成環的那條邊」。

## 第五題：路徑數量

最後一題是 Count Paths，也就是 Unique Paths。一個 m 乘 n 的網格，機器人從左上角出發，每次只能往右或往下，問走到右下角有幾種不同的路徑。

遞推式你寫在註解裡了：走到某一格的方法數，等於從上面那格下來的方法數，加上從左邊那格過來的方法數。第一行和第一列都只有一種走法，因為只能一直往右或一直往下。

你直接寫成了一維陣列的版本。陣列一開始全部是一，代表第一行。接著每處理新的一行，就從第二欄開始，讓 dp 的 c 加上 dp 的 c 減一。這一行程式碼很巧妙：加之前，dp 的 c 還是上一行的值，代表「從上面來」；dp 的 c 減一已經是這一行更新過的值，代表「從左邊來」。由左往右更新，一個陣列就同時保有了上面和左邊的資訊。

這跟第二題的滾動陣列是同一個概念，只是這裡更進一步，連兩個陣列都不用，因為只需要上面和左邊，不需要左上角。時間是 m 乘 n，空間是 n。

延伸一下：這題也有組合數學的解法。總共要往下走 m 減一步、往右走 n 減一步，答案就是從 m 加 n 減二步中，挑出 m 減一步往下的組合數。關鍵句：「上面加左邊；由左往右更新，一個陣列就夠」。
